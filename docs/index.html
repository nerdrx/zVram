Experimental boundary: compression applies only to buffers explicitly managed by the Vulkan pool. The HIP fallback uses pinned host RAM. Neither path claims transparent arbitrary-app compression or a gain over native driver behavior.

Measured on hardware

40 GiB data. 256 MiB budget.

The managed pool verified every word after GPU mutation, eviction, and restoration. Its highly compressible constant pattern stored 3,998,720 bytes under a 256 MiB resident budget; this is not representative of model weights. A report-enabled HIP VMM/GTT check verified one 40 GiB pointer backed by 20 GiB VRAM and 20 GiB GTT, with logical free capacity returning from 40 GiB to zero while allocated and back after free. An 80 MiB check agreed across three HIP APIs. By default HIP still reports physical capacity. These synthetic checks do not establish model compatibility, a native HIP capacity gain, or transparent paging.

The current prototype

Three experiments. Explicit limits.

01 / TELEMETRY

See allocation behavior

An opt-in layer records allocation activity and requests AMD RADV overallocation when supported. The native driver remains responsible for migration into system RAM.

Vulkan layerAMD RADV
02 / VULKAN POOL

Evict and restore safely

A C++ API owns explicit buffers, pins them while in use, and stores lossless zstd or raw snapshots under a host budget. Applications refresh VkBuffer references after restore.

Bounded host storeC++17 API
03 / HIP FALLBACK

Route capped allocations

An optional hipMalloc shim supports native device allocations, mapped pinned host fallback, and an experimental one-pointer VMM/GTT provider. Logical capacity reporting is opt-in and limited to three HIP APIs; these paths are not compressed and broader application integration remains untested.

Opt-inPinned host RAM

Try the prototype

Build. Inspect. Experiment.

Requires Vulkan headers, glslc, and zstd development files. HIP checks need ROCm; VMM/GTT also needs libdrm AMDGPU development files.

SHELL
# Get the source
git clone https://github.com/nerdrx/zVram.git
cd zVram

# Configure and build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Run the managed Vulkan integrity check
./zvram --validate --isolate-layers -- ./build/zvram-managed-check

# HIP VMM/GTT, with opt-in capacity reporting through supported HIP queries
./zvram --hip --hip-vmm --hip-report-capacity \
  --hip-local-mib 20480 --hip-host-mib 20480 -- \
  ./build/hip_check --single-allocation --mib 40960
