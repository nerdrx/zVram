Measured on hardware

Capacity verified. Compression measured.

One 40 GiB Vulkan buffer passed full readback through 160 native chunks; full 96 GiB backing remains unverified. A 320 MiB Vulkan idle-snapshot test released 320 MiB of process resident VRAM and passed full-byte wake checks, including partial-freeze/restore-retry cases. A 14 MiB cold-store test also verified that releasing one cold buffer lets a second freeze and restore without new GPU work; the current 39-test GPU suite passed. An unchanged 135M F16 Vulkan llama.cpp run matched native output after automatic snapshots. An official 39.73 GB InternLM2.5-20B F16 model loaded through HIP VMM/GTT with a 36,798.77 MiB GPU model buffer and all 49 layers offloaded; native full-GPU HIP allocation OOMed. Native partial HIP offload matched VMM output, and the model also completed through zVram's Vulkan virtual heap with output matching native Vulkan. llama.cpp n-gram self-drafting reached 6.33 vs 1.10 tokens/s on repeated text, but only 1.45 vs 1.43 on ordinary prose, where transcripts differed. These are short app-level tests, not a zVram or general speedup claim. A 40 GiB GPU model buffer remains untested. One 40 GiB HIP pointer also passed GPU-write verification using 20 GiB VRAM and 20 GiB GTT; unchanged 30B and 27B models ran concurrently with 34.2 GB of combined GPU model buffers.

The existing 27B Q4_K_M HIP model matched output after idle restore with fully VRAM-resident active buffers: native 24.41 versus automatic 24.33 tokens/s over 45 decode runs each. Idle process VRAM fell from 16.30 GB to 0.155 GB; cold payload saved 2.86%, with a 12.9-second wake. The earlier forced-spill placement measured about 3 tokens/s and used a different memory placement.

The current prototype

Three experiments. Explicit limits.

01 / TELEMETRY

See allocation behavior

An opt-in layer can expose a configurable 96 GiB logical heap for eligible storage buffers, using stable sparse buffers backed by native chunks. A 40 GiB allocation passed full readback. Virtual-only queue forwarding passed seven focused tests; unrelated app queues avoid device-wide snapshot locks and cold scans. Idle snapshots remain a separate path and passed one unchanged 135M F16 llama.cpp Vulkan run. Broader model and API coverage remains untested.

Vulkan virtual heapAMD RADV
02 / VULKAN POOL

Evict and restore safely

A C++ API owns explicit buffers, pins them while in use, and stores lossless zstd or raw snapshots under a host budget. Default buffers need refreshed references after restore; an optional sparse mode preserves their handles at explicit acquire/release boundaries.

Bounded host storeC++17 API
03 / HIP FALLBACK

Route capped allocations

An optional hipMalloc shim supports native device allocations, mapped pinned host fallback, and an experimental VMM/GTT provider. Explicit userspace hibernate/resume preserves GPU pointers with compressed cold backing. On the tested ROCm HIP 7.2.53211 dispatch ABI, opt-in idle hooks snapshot tracked VMM allocations and restore them before work. The small 135M F16 llama.cpp check matched native output; the existing 27B model also passed idle restore and identical-output checks.

Optional HIP allocation fallback

GPU-write integrity passed across native and host tiers. The 39.73 GB InternLM2.5-20B F16 model ran through VMM/GTT after the native full-GPU allocation OOMed; a separate 24/49-layer native CPU/GPU run matched its output. A 40 GiB GPU model buffer remains untested.

Native Linux reclaim

A scoped dmem probe verified every byte of 64 MiB under a 16 MiB VRAM limit. RAM migration passed; swap compression remains unproven.

●
NOW

HIP VMM with GTT backing

A 39.73 GB InternLM2.5-20B F16 model loaded with 49/49 layers and a 36,798.77 MiB GPU model buffer; native full-GPU allocation OOMed. Partial native offload matched output at 1.38 tokens/s versus VMM at 1.09. One 40 GiB pointer passed integrity; a 40 GiB GPU model buffer remains untested.

●
NOW

Userspace HIP cold snapshots

32 MiB and 288 MiB allocations passed lossless restore, native readback, stable pointers, and failure recovery. Measured process backing was released while cold. Explicit lifecycle only; no root service needed.

●
NOW

HIP automatic idle snapshots

Opt-in idle hibernation and restore passed on HIP 7.2.53211 with the tested dispatch ABI, including a small unchanged 135M F16 llama.cpp run. Other ABI versions disable this mode; raw HSA/direct submissions and broader app paths are outside its coverage.

Native GPU-only allocations and stable device addresses passed full-byte checks across multiple queues. An unchanged 135M F16 model also matched native output after automatic restore.

Try the prototype

Build. Inspect. Experiment.

Requires Vulkan headers, glslc, and zstd development files. HIP checks need ROCm; VMM/GTT also needs libdrm AMDGPU development files.

SHELL
# Get the source
git clone https://github.com/nerdrx/zVram.git
cd zVram

# Configure and build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Run the managed Vulkan integrity check
./zvram --validate --isolate-layers -- ./build/zvram-managed-check

# 96 GiB logical heap, bounded 2 GiB memtest payload
./zvram --verbose --isolate-layers --vulkan-virtual-gib 96 -- \
  memtest_vulkan 1 2147483648

# Narrow 320 MiB automatic Vulkan idle-snapshot check
./zvram --verbose --isolate-layers --vulkan-virtual-gib 96 \
  --vulkan-auto-idle-ms 100 --vulkan-cold-mib 512 -- \
  ./build/zvram-vulkan-auto-check

# Compare an unchanged Vulkan llama-completion run with idle snapshots
python3 check_vulkan_idle_model.py --binary /path/to/llama-completion \
  --model /path/to/SmolLM2-135M-F16.gguf

# HIP VMM/GTT, with opt-in capacity reporting through supported HIP queries
./zvram --hip --hip-vmm --hip-report-capacity \
  --hip-local-mib 20480 --hip-host-mib 20480 -- \
  ./build/hip_check --single-allocation --mib 40960

# Experimental automatic compression after an idle interval
./zvram --hip --hip-vmm --hip-local-mib 64 --hip-host-mib 2048 \
  --hip-auto-idle-ms 1000 --hip-cold-mib 1024 -- \
  ./your-hip-application
