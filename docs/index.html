i

Experimental boundary: compression applies to explicitly managed Vulkan buffers and opt-in HIP idle hibernation for tracked VMM allocations on one tested ROCm ABI. HIP can expand allocations with mapped host RAM or GTT backing; the GTT path verified a 40 GiB single allocation that native HIP rejected on this machine. Idle hibernation is process-level; the full active working set must still fit in VRAM plus GTT.

Measured on hardware

Capacity verified. Compression measured.

One 40 GiB Vulkan buffer passed full readback through 160 native chunks in 17.45 seconds. The heap size is selectable at launch, with no artificial upper cap. A 48 GiB setting passed a bounded 2 GiB unchanged memtest check; full 48 GiB usage remains unverified. One 40 GiB HIP pointer passed full GPU-write verification using 20 GiB VRAM and 20 GiB GTT; native HIP rejected that single allocation. Unchanged 30B and 27B models ran concurrently with 34.2 GB of combined GPU model buffers on the 24 GiB card. A small unchanged 135M F16 llama.cpp run with HIP graph capture disabled also matched native stdout with automatic idle compression enabled and all 31/31 layers offloaded: 307,704,064 logical cold bytes compressed to 206,994,149 retained bytes. The existing 27B Q4_K_M model matched output after hibernation with fully VRAM-resident active buffers: native 24.41 versus automatic 24.33 tokens/s over 45 decode runs each (0.33% lower in this short run). Idle process VRAM fell from 16.30 GB to 0.155 GB. Cold payload saved 2.86%, and waking took 12.9 seconds. An earlier forced-spill placement measured about 3 tokens/s; that was a different memory placement. A 40 GiB model remains untested.

The current prototype

Three experiments. Explicit limits.

01 / TELEMETRY

See allocation behavior

An opt-in layer can expose a configurable 48 GiB logical heap for eligible storage buffers, using stable sparse buffers backed by native chunks. One 40 GiB allocation passed full readback; unchanged memtest displayed 48 GB in a 2 GiB check. Native migration supplies RAM backing; Vulkan compression is still pending.

Vulkan virtual heapAMD RADV
02 / VULKAN POOL

Evict and restore safely

A C++ API owns explicit buffers, pins them while in use, and stores lossless zstd or raw snapshots under a host budget. Default buffers need refreshed references after restore; an optional sparse mode preserves their handles at explicit acquire/release boundaries.

Bounded host storeC++17 API
03 / HIP FALLBACK

Route capped allocations

An optional hipMalloc shim supports native device allocations, mapped pinned host fallback, and an experimental VMM/GTT provider. Explicit userspace hibernate/resume preserves GPU pointers with compressed cold backing. On the tested ROCm HIP 7.2.53211 dispatch ABI, opt-in idle hooks snapshot tracked VMM allocations and restore them before work. The small 135M F16 llama.cpp check matched native output; the existing 27B model also passed idle restore and identical-output checks.

Research direction

Prototype today. Learn what’s next.

NOW

Managed Vulkan pool

Chunked snapshots and LRU compute checks passed; optional sparse backing also preserved buffer handles under a 2 MiB resident budget.

●
NOW

Optional HIP allocation fallback

GPU-write integrity verified across native and host tiers; an unchanged ROCm copy example and concurrent 30B/27B models also passed. Native HIP rejected one 40 GiB allocation; VMM/GTT accepted it. A 40 GiB model remains untested.

●
TESTED

Native Linux reclaim

A scoped dmem probe verified every byte of 64 MiB under a 16 MiB VRAM limit. RAM migration passed; swap compression remains unproven.

●
NOW

HIP VMM with GTT backing

One 40 GiB pointer passed GPU-write/CPU-verify using 20 GiB VRAM and 20 GiB GTT; 30B and 27B models also ran together with 34.2 GB of GPU model buffers. A single 40 GiB model remains untested.

●
NOW

Userspace HIP cold snapshots

32 MiB and 288 MiB allocations passed lossless restore, native readback, stable pointers, and failure recovery. Measured process backing was released while cold. Explicit lifecycle only; no root service needed.

●
NOW

HIP automatic idle snapshots

Opt-in idle hibernation and restore passed on HIP 7.2.53211 with the tested dispatch ABI, including a small unchanged 135M F16 llama.cpp run. Other ABI versions disable this mode; raw HSA/direct submissions and broader app paths are outside its coverage.

●
NEXT

Broader workloads

Measure performance at normal GPU placement and more application paths. A single 40 GiB model and universal paging remain untested.

Try the prototype

Build. Inspect. Experiment.

Requires Vulkan headers, glslc, and zstd development files. HIP checks need ROCm; VMM/GTT also needs libdrm AMDGPU development files.

SHELL
# Get the source
git clone https://github.com/nerdrx/zVram.git
cd zVram

# Configure and build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Run the managed Vulkan integrity check
./zvram --validate --isolate-layers -- ./build/zvram-managed-check

# HIP VMM/GTT, with opt-in capacity reporting through supported HIP queries
./zvram --hip --hip-vmm --hip-report-capacity \
  --hip-local-mib 20480 --hip-host-mib 20480 -- \
  ./build/hip_check --single-allocation --mib 40960

# Experimental automatic compression after an idle interval
./zvram --hip --hip-vmm --hip-local-mib 64 --hip-host-mib 2048 \
  --hip-auto-idle-ms 1000 --hip-cold-mib 1024 -- \
  ./your-hip-application
