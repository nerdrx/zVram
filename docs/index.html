For ranges above 32 MiB, snapshot decode can use up to three background workers plus the calling thread into existing staging (bounded to 128 MiB); freeze/restore batches up to four 32 MiB frames per GPU copy/wait. The current pipeline adds two host staging slots of at most 128 MiB each, overlapping CPU decode of the next admitted child with the GPU copy. It uses at most four CPU decode workers per restoration; whole-pool and oversized snapshots stay serial, and GPU allocations remain within resident admission. The current prototype

Three experiments. Explicit limits.

01 / TELEMETRY

See allocation behavior

An opt-in layer can expose a configurable 96 GiB logical heap for eligible storage buffers, using stable sparse buffers backed by native chunks. A 40 GiB allocation passed full readback. The separate --vulkan-range-mib 32 mode uses sparse chunk ranges for selective restore and eviction; a 64 MiB check and one unchanged 135M F16 run passed. Broader model and API coverage remains untested.

Vulkan virtual heapAMD RADV
02 / VULKAN POOL

Evict and restore safely

A C++ API owns explicit buffers, pins them while in use, and stores lossless zstd or raw snapshots under a host budget. Default buffers need refreshed references after restore; an optional sparse mode preserves their handles at explicit acquire/release boundaries. The experimental Vulkan layer can also retain verified compressed ranges under a shared cold-store quota when read-only access is proven.

Bounded host storeC++17 API
03 / HIP FALLBACK

Route capped allocations

An optional hipMalloc shim supports native device allocations, mapped pinned host fallback, and an experimental VMM/GTT provider. Explicit userspace hibernate/resume preserves GPU pointers with compressed cold backing. On the tested ROCm HIP 7.2.53211 dispatch ABI, opt-in idle hooks snapshot tracked VMM allocations and restore them before work. The small 135M F16 llama.cpp check matched native output; the existing 27B model also passed idle restore and identical-output checks.

Try the prototype

Build. Inspect. Experiment.

Requires Vulkan headers, glslc, and zstd development files. HIP checks need ROCm; VMM/GTT also needs libdrm AMDGPU development files.

SHELL
# Get the source
git clone https://github.com/nerdrx/zVram.git
cd zVram

# Configure and build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Run the managed Vulkan integrity check
./zvram --validate --isolate-layers -- ./build/zvram-managed-check

# 96 GiB logical heap, bounded 2 GiB memtest payload
./zvram --verbose --isolate-layers --vulkan-virtual-gib 96 -- \
  memtest_vulkan 1 2147483648

# Narrow 320 MiB automatic Vulkan idle-snapshot check
./zvram --verbose --isolate-layers --vulkan-virtual-gib 96 \
  --vulkan-auto-idle-ms 100 --vulkan-cold-mib 512 -- \
  ./build/zvram-vulkan-auto-check

# Active whole-allocation eviction during tracked queue work
./zvram --validate --isolate-layers --vulkan-virtual-mib 64 \
  --vulkan-auto-idle-ms 100 --vulkan-cold-mib 64 \
  --vulkan-selective-restore --vulkan-active-eviction -- \
  ./build/zvram-vulkan-auto-check --active-submit --two-queues

# Opt-in 32 MiB sparse range residency
./zvram --validate --isolate-layers --vulkan-virtual-mib 64 \
  --vulkan-auto-idle-ms 100 --vulkan-cold-mib 64 \
  --vulkan-selective-restore --vulkan-active-eviction --vulkan-range-mib 32 -- \
  ./build/zvram-vulkan-auto-check --range-submit

# Compare an unchanged Vulkan llama-completion run with idle snapshots
python3 check_vulkan_idle_model.py --binary /path/to/llama-completion \
  --model /path/to/SmolLM2-135M-F16.gguf

# HIP VMM/GTT, with opt-in capacity reporting through supported HIP queries
./zvram --hip --hip-vmm --hip-report-capacity \
  --hip-local-mib 20480 --hip-host-mib 20480 -- \
  ./build/hip_check --single-allocation --mib 40960

# Experimental automatic compression after an idle interval
./zvram --hip --hip-vmm --hip-local-mib 64 --hip-host-mib 2048 \
  --hip-auto-idle-ms 1000 --hip-cold-mib 1024 -- \
  ./your-hip-application
