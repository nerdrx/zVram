Measured on hardware

Capacity verified. Compression measured.

One 40 GiB Vulkan buffer passed full readback through 160 native chunks; full 96 GiB backing remains unverified. A 320 MiB Vulkan idle-snapshot test released 320 MiB of process resident VRAM and passed full-byte wake checks, including partial-freeze/restore-retry cases. The latest full CTest suite passed 86/86 in 56.75 seconds with zero validation errors or VUIDs. A 512 MiB allocation passed full-byte checks with three nonoverlapping promoted storage buffers in synthetic and adopted native memory, including snapshots across allocation gaps. An unchanged 135M F16 Vulkan model also passed 11 selective-restore checks with identical native output, 31/31 layers, and zero fallback. An official 39.73 GB InternLM2.5-20B F16 model loaded through HIP VMM/GTT with a 36,798.77 MiB GPU model buffer and all 49 layers offloaded; native full-GPU HIP allocation OOMed. Native partial HIP offload matched VMM output, and the model also completed through zVram's Vulkan virtual heap with output matching native Vulkan. llama.cpp n-gram self-drafting reached 6.33 vs 1.10 tokens/s on repeated text, but only 1.45 vs 1.43 on ordinary prose, where transcripts differed. These are short app-level tests, not a zVram or general speedup claim. A 40 GiB GPU model buffer remains untested. One 40 GiB HIP pointer also passed GPU-write verification using 20 GiB VRAM and 20 GiB GTT; unchanged 30B and 27B models ran concurrently with 34.2 GB of combined GPU model buffers.

The five-case active-eviction gate passed across synthetic and adopted native pools. B restored and passed byte checks before A's host-gated queue was released; the watchdog did not fire. Unknown command use kept both pools resident for 300 ms. A separate unchanged 135M model run passed 12 checks with identical output and cold restore; it does not establish a speedup. This confirms a narrow allocation-granularity path, not 40 GiB compression speed, VRChat compatibility, or broad workload behavior. Read the focused evidence and limits.

The opt-in --vulkan-range-mib 32 path passed 4/4 focused checks. An unchanged 135M model passed 13/13 checks with identical output; one submission selected ten chunks together. The --vulkan-resident-mib 192 check passed 21/21 model checks and the focused resident-pressure gate passed 6/6; after full cold startup, tracked backing peaked at 165.8125 MiB, with 354 evictions and identical native/wrapped output. A paired clean-snapshot cache run passed 25/25 with identical output, 405 cache reuses, and 3 invalidations. In short separate decode runs, the pressure baseline measured 2.82 tokens/s and cached mode 6.23; native runs measured 123.25 and 123.74 tokens/s. These workload-specific figures are not a general speed claim. Six focused synthetic/native checks also verified read-only reuse, dirty writes, quota trimming, and accepted unknown writes. The cache shares a bounded cold-store quota and is limited to proven read-only accesses. This is not a global VRAM cap or proof of 40 GiB streaming or game behavior. Read clean-cache evidence and limits.

The opt-in --vulkan-eviction-policy lru|mru selects the eligible completed chunk chosen first under resident admission; LRU remains the default. A matched small-model scan pair passed 26/26 checks each with identical output. One run measured 8.36 tokens/s for MRU versus 6.23 for LRU; native references were 119.43 and 122.04 tokens/s. Peak tracked backing was 185.875 MiB for MRU and 165.8125 MiB for LRU, under the 192 MiB limit. MRU restored 8,640 MiB versus LRU's 13,056 MiB. These single-run results have throughput variance and do not establish 40 GiB behavior or game performance. The helper's optional --min-available-mib stops its child process group at a system-wide available-memory floor; it is not a hard allocation cap. Read policy evidence and limits.

A longer-idle MRU run completed an unchanged 16.8107 GB Q4 model under a 12 GiB tracked-residency cap: 26/26 checks, identical native/wrapped output, 66/66 layers, and 4,952 pressure admissions. Wrapped decode was 0.28 tokens/s versus 6.00 native, so this is a functional result with a substantial slowdown. There is no large-model LRU comparison; this is not a 40 GB model or game result. Read the run details.

The existing 27B Q4_K_M HIP model matched output after idle restore with fully VRAM-resident active buffers: native 24.41 versus automatic 24.33 tokens/s over 45 decode runs each. Idle process VRAM fell from 16.30 GB to 0.155 GB; cold payload saved 2.86%, with a 12.9-second wake. The earlier forced-spill placement measured about 3 tokens/s and used a different memory placement.

The current prototype

Three experiments. Explicit limits.

01 / TELEMETRY

See allocation behavior

An opt-in layer can expose a configurable 96 GiB logical heap for eligible storage buffers, using stable sparse buffers backed by native chunks. A 40 GiB allocation passed full readback. The separate --vulkan-range-mib 32 mode uses sparse chunk ranges for selective restore and eviction; a 64 MiB check and one unchanged 135M F16 run passed. Broader model and API coverage remains untested.

Vulkan virtual heapAMD RADV
02 / VULKAN POOL

Evict and restore safely

A C++ API owns explicit buffers, pins them while in use, and stores lossless zstd or raw snapshots under a host budget. Default buffers need refreshed references after restore; an optional sparse mode preserves their handles at explicit acquire/release boundaries. The experimental Vulkan layer can also retain verified compressed ranges under a shared cold-store quota when read-only access is proven.

Bounded host storeC++17 API
03 / HIP FALLBACK

Route capped allocations

An optional hipMalloc shim supports native device allocations, mapped pinned host fallback, and an experimental VMM/GTT provider. Explicit userspace hibernate/resume preserves GPU pointers with compressed cold backing. On the tested ROCm HIP 7.2.53211 dispatch ABI, opt-in idle hooks snapshot tracked VMM allocations and restore them before work. The small 135M F16 llama.cpp check matched native output; the existing 27B model also passed idle restore and identical-output checks.

Native Linux reclaim

A scoped dmem probe verified every byte of 64 MiB under a 16 MiB VRAM limit. RAM migration passed; swap compression remains unproven.

HIP VMM with GTT backing

A 39.73 GB InternLM2.5-20B F16 model loaded with 49/49 layers and a 36,798.77 MiB GPU model buffer; native full-GPU allocation OOMed. Partial native offload matched output at 1.38 tokens/s versus VMM at 1.09. One 40 GiB pointer passed integrity; a 40 GiB GPU model buffer remains untested.

NOW

Userspace HIP cold snapshots

32 MiB and 288 MiB allocations passed lossless restore, native readback, stable pointers, and failure recovery. Measured process backing was released while cold. Explicit lifecycle only; no root service needed.

NOW

HIP automatic idle snapshots

Opt-in idle hibernation and restore passed on HIP 7.2.53211 with the tested dispatch ABI, including a small unchanged 135M F16 llama.cpp run. Other ABI versions disable this mode; raw HSA/direct submissions and broader app paths are outside its coverage.

Vulkan automatic snapshots and active eviction

Native GPU-only allocations and stable device addresses passed full-byte checks across multiple queues. A focused active test compressed and restored an unused whole allocation while another tracked queue remained pending; unknown commands protected all pools. Opt-in 32 MiB range residency passed a two-chunk check and one unchanged small-model run; broader workloads remain untested.

Try the prototype

Build. Inspect. Experiment.

Requires Vulkan headers, glslc, and zstd development files. HIP checks need ROCm; VMM/GTT also needs libdrm AMDGPU development files.

SHELL
# Get the source
git clone https://github.com/nerdrx/zVram.git
cd zVram

# Configure and build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Run the managed Vulkan integrity check
./zvram --validate --isolate-layers -- ./build/zvram-managed-check

# 96 GiB logical heap, bounded 2 GiB memtest payload
./zvram --verbose --isolate-layers --vulkan-virtual-gib 96 -- \
  memtest_vulkan 1 2147483648

# Narrow 320 MiB automatic Vulkan idle-snapshot check
./zvram --verbose --isolate-layers --vulkan-virtual-gib 96 \
  --vulkan-auto-idle-ms 100 --vulkan-cold-mib 512 -- \
  ./build/zvram-vulkan-auto-check

# Active whole-allocation eviction during tracked queue work
./zvram --validate --isolate-layers --vulkan-virtual-mib 64 \
  --vulkan-auto-idle-ms 100 --vulkan-cold-mib 64 \
  --vulkan-selective-restore --vulkan-active-eviction -- \
  ./build/zvram-vulkan-auto-check --active-submit --two-queues

# Opt-in 32 MiB sparse range residency
./zvram --validate --isolate-layers --vulkan-virtual-mib 64 \
  --vulkan-auto-idle-ms 100 --vulkan-cold-mib 64 \
  --vulkan-selective-restore --vulkan-active-eviction --vulkan-range-mib 32 -- \
  ./build/zvram-vulkan-auto-check --range-submit

# Compare an unchanged Vulkan llama-completion run with idle snapshots
python3 check_vulkan_idle_model.py --binary /path/to/llama-completion \
  --model /path/to/SmolLM2-135M-F16.gguf

# HIP VMM/GTT, with opt-in capacity reporting through supported HIP queries
./zvram --hip --hip-vmm --hip-report-capacity \
  --hip-local-mib 20480 --hip-host-mib 20480 -- \
  ./build/hip_check --single-allocation --mib 40960

# Experimental automatic compression after an idle interval
./zvram --hip --hip-vmm --hip-local-mib 64 --hip-host-mib 2048 \
  --hip-auto-idle-ms 1000 --hip-cold-mib 1024 -- \
  ./your-hip-application
