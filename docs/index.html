Experimental boundary: compression applies to buffers explicitly managed by the Vulkan pool. HIP can expand allocations with mapped host RAM or GTT backing; the GTT path verified a 40 GiB single allocation that native HIP rejected on this machine. Transparent arbitrary-app compression remains future work.

Measured on hardware

Capacity verified. Compression measured.

One 40 GiB HIP pointer passed full GPU-write verification using 20 GiB VRAM and 20 GiB GTT; native HIP rejected that single allocation. Unchanged 30B and 27B models ran concurrently with 34.2 GB of combined GPU model buffers on the 24 GiB card. A small llama.cpp run also produced identical native and zVram output. Separately, a 270.9 MB F16 model file compressed losslessly to 207.3 MB (23.5% saved), with every byte restored under a 16 MiB resident budget. These checks cover specific paths; a 40 GiB model and transparent application compression remain untested.

The current prototype

Three experiments. Explicit limits.

01 / TELEMETRY

See allocation behavior

An opt-in layer records allocation activity and requests AMD RADV overallocation when supported. The native driver remains responsible for migration into system RAM.

Vulkan layerAMD RADV
02 / VULKAN POOL

Evict and restore safely

A C++ API owns explicit buffers, pins them while in use, and stores lossless zstd or raw snapshots under a host budget. Default buffers need refreshed references after restore; an optional sparse mode preserves their handles at explicit acquire/release boundaries.

Bounded host storeC++17 API
03 / HIP FALLBACK

Route capped allocations

An optional hipMalloc shim supports native device allocations, mapped pinned host fallback, and an experimental one-pointer VMM/GTT provider. Unchanged 30B and 27B llama.cpp models ran together, and a ROCm copy example passed; logical capacity reporting is limited to three HIP APIs, and broader application integration remains untested.

Try the prototype

Build. Inspect. Experiment.

Requires Vulkan headers, glslc, and zstd development files. HIP checks need ROCm; VMM/GTT also needs libdrm AMDGPU development files.

SHELL
# Get the source
git clone https://github.com/nerdrx/zVram.git
cd zVram

# Configure and build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Run the managed Vulkan integrity check
./zvram --validate --isolate-layers -- ./build/zvram-managed-check

# HIP VMM/GTT, with opt-in capacity reporting through supported HIP queries
./zvram --hip --hip-vmm --hip-report-capacity \
  --hip-local-mib 20480 --hip-host-mib 20480 -- \
  ./build/hip_check --single-allocation --mib 40960
